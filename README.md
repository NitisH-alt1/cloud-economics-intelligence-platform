# Cloud Economics Intelligence Platform

## Current application

The local website is served by `web.app:app` on port `8090`. It provides login, signup, and the authenticated workspace. The FastAPI application in `dashboard.app:app` serves the API on port `8081`. PostgreSQL is configured for host port `5433` by `database/docker-compose.postgres.yml`.

The API includes organization-scoped authentication, projects, cloud-account records, connection records, project/account associations, and project-scoped cost and analysis routes. See the FastAPI OpenAPI page at `/docs` when the API is running.

## Data and analysis status

Project cost records currently contain deterministic local demo estimates, not provider billing data. Cloud-account records and connection records do not validate provider credentials or enable ingestion. Causal results are model-derived candidates for investigation, not proof of causality. Anomaly signals use the included analyzer sample data.

## Repository structure

- `analyzer/` — anomaly detection, dependency graphs, causal candidate scoring, and cost attribution.
- `auth/` — authentication, organization-scoped APIs, projects, cloud accounts, connections, and intelligence.
- `dashboard/` — FastAPI API application, configuration, logging, and security middleware.
- `database/` — SQLAlchemy models, initialization, and the local PostgreSQL Compose file.
- `data/` — included sample inputs and analysis outputs.
- `deployment/` — local launchers, wiring scripts, and security notes.
- `services/` — instrumented checkout, inventory, and payment demo services.
- `web/` — website routes, pages, styles, and browser assets.

The root `docker-compose.yml` defines the local observability and instrumented-service stack. PostgreSQL is started separately. The Compose host ports bind to loopback for local use.

## Production configuration

### Render + Supabase preparation

The repository contains a Render Blueprint for two Python web services because the website (`web.app:app`) and API (`dashboard.app:app`) are separate FastAPI applications. The website serves HTML and static assets; it is not a static-site build. Each service binds to Render's injected `PORT` and has a `/health` check. The Blueprint does not deploy anything by itself.

Configure these values in Render after creating the services:

- API service: `DATABASE_URL` set to the Supabase **Session pooler** PostgreSQL URI (port `5432`, with SSL required, as supplied by Supabase), `JWT_SECRET_KEY` generated by Render, and `CORS_ORIGINS` set to the exact HTTPS origin of the website service. Use the Session pooler because Render's outbound network is IPv4-only and Supabase's direct endpoint is IPv6 by default; session mode also supports the application's persistent PostgreSQL connection model.
- Website service: `API_BASE_URL` set to the API service's public HTTPS origin, without a trailing slash.
- Both services: `APP_ENV=production` on the API is set by the Blueprint. No database credentials or signing keys belong in browser variables or source control.

The API requires `DATABASE_URL` and `JWT_SECRET_KEY` in production and fails startup when either is absent. Render's generated secret is not committed. Do not set Supabase API keys: this application connects through PostgreSQL using `DATABASE_URL` and does not currently use the Supabase HTTP API.

For local development, keep using `deployment/start-website.ps1` on port `8090` and `deployment/start-production.ps1` on port `8081`; the website's runtime API config defaults to same-host port `8081` when `API_BASE_URL` is unset. Local PostgreSQL remains on host port `5433`.
